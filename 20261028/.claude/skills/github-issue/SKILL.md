# Github Issue 등록

> 워크플로우의 `2. Github Issues` 단계를 수행하는 스킬.
>
> 이 스킬은 절차와 멘트 규격만 정의한다. 작성 규칙의 원본은 아래 지침 문서이며, 규칙을 이 스킬에 복사하지 않는다.

---

## 참조 문서 (필요 섹션만 읽는다)

| 시점 | 문서 | 읽을 섹션 |
| --- | --- | --- |
| 1단계 | `Docs\Claude\WorkflowRules.md` | `1. 업무 유형`, `2. Github Issues` |
| 3단계 | `Docs\Documentation\Github Issue Rule.md` | 전체 (`1. Title` ~ `7. 기타`) |
| 3단계 | `Docs\Template\IssueTemplate.md` | 양식 코드블록 |

- 읽지 않은 섹션을 읽었다고 가정하지 않는다.
- 문서에 접근할 수 없으면 그 사실을 알리고 중단한다.

---

## 절차

### 1단계. 대상 판단

- `WorkflowRules.md`의 `1. 업무 유형`으로 업무 유형을 구분한다.
- 문서 작업이면 이슈를 등록하지 않고 종료한다.
- 유형이 불분명하면 임의로 정하지 않고 질문한다.

### 2단계. 등록 권유

- 이슈가 필요하다고 판단하면 아래 **[멘트 A]** 로 권유한다.
- 사용자가 이슈 없이 진행하겠다고 하면 스킬을 종료한다.

### 3단계. 정보 수집

- `Github Issue Rule.md`의 `2. 배경 / 목적`에 따라 배경/목적을 사용자에게 질문한다.
  - 답을 받지 못하면 이슈 작성을 거부한다.
- 그 외 섹션은 대화 내용과 프로젝트 문서를 근거로 초안을 만든다. 근거가 없는 내용은 지어내지 않고 질문한다.
- Label은 `gh label list`로 등록 여부를 확인한다. 미등록이면 `7. 기타 > Label` 규칙에 따라 새로 등록할지 질문한다.

### 4단계. 작성 전 승인

- `IssueTemplate.md` 양식으로 본문 초안을 만들고 아래 **[멘트 B]** 로 승인을 요청한다.
- 수정 요청을 받으면 반영 후 **[멘트 B]** 를 다시 출력한다.
- 명시적인 승인 전에는 등록하지 않는다.

### 5단계. 등록

- 승인 후 `gh issue create`로 등록한다. 본문은 파일(`--body-file`)로 전달한다.
- 등록 후 아래 **[멘트 C]** 로 결과를 보고한다.
- 이후 워크플로우의 `3. 브랜치 생성` 단계에 따라 사용자의 브랜치 생성과 착수명령을 기다린다.

---

## 멘트 규격

> 아래 형식을 그대로 사용한다. 각 항목은 한 줄로 간결하게 쓰고, 형식에 없는 설명을 덧붙이지 않는다.

### [멘트 A] 이슈 등록 권유

```markdown
## 이슈 등록 권유

- **업무 유형** : [개발 / 버그 수정]
- **예상 제목** : [기능 단위 제목]
- **권유 근거** : [이슈가 필요한 이유 한 줄]

이슈를 등록할까요? (등록 / 이슈 없이 진행)
등록한다면 **배경 / 목적**을 알려주세요.
```

### [멘트 B] 작성 전 승인 요청

```markdown
## 이슈 등록 확인

- **Title** : [제목]
- **Label** : [Label]

**본문 미리보기**
> [IssueTemplate.md 양식으로 작성한 본문을 인용 블록으로 표시]

- **확인 필요** : [근거가 부족해 사용자 확인이 필요한 항목 / 없으면 "없음"]

이대로 등록할까요? (승인 / 수정 요청)
```

### [멘트 C] 등록 결과 보고

```markdown
## 이슈 등록 완료

- **Issue** : #[번호] [제목]
- **링크** : [URL]
- **다음 단계** : 브랜치를 생성한 뒤 착수명령을 내려주세요.
```
