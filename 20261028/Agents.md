## 구현 원칙
- 현재 작업에 필요한 기능만 구현한다.
- 기존 코드의 구조와 명명 규칙을 우선 따른다.
- 기존 기능을 삭제하거나 동작을 변경해야 한다면 이유를 설명한다.
- 미정인 기획을 확정된 요구사항처럼 구현하지 않는다.
- 작은 구현 선택은 합리적으로 판단하고 결과에 기록한다.
- 게임 규칙, 플랫폼, 유료 패키지 도입처럼 영향이 큰 선택은 질문한다.
- API 키, 비밀번호, 인증 정보는 코드에 작성하지 않는다.

## 문서 해석
- '확정'은 구현 기준이다.
- '미정'은 임의로 확정하지 않는다.
- '가정'은 임시 판단이며 변경 가능하다.
- 문서 간 요구사항이 충돌하면 충돌 내용을 설명하고 확인한다.

## 규칙 적용 순서
- 사용자의 현재 명시적 요청을 우선한다.
- 프로젝트에서 명시한 예외는 공통 규칙보다 우선한다.
- 예외가 없는 항목에는 공통 규칙을 적용한다.
- 요구사항이 서로 충돌하고 우선순위로 해결되지 않으면 질문한다.
